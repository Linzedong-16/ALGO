## 自研埋点SDK设计

1. 初始化全局参数：项目ID、环境标识、上报地址等，全局单例防止多次实例化
2. 异常与行为：全局监听捕获JS报错异常、接口异常、页面PV和用户各种行为（路由、滚动、点击）
3. 统一格式化：统一数据格式并做用户隐私信息的脱敏
4. 上传处理：内存队列采集，同步离线缓存 + 按阈值上报减少请求次数，通过sendBeacon以及打点
5. 精细化要求：对外提供手动埋点API 搭配采样 去重 白名单策略减少无效上报

## 第一层：初始化配置全局参数

SDK 引入页面后，先做初始化。
在这里设置项目 ID、环境、用户基础信息、采样率、上报地址这些全局配置，后续所有采集事件都会带上这份基础信息。

## 第二层：全局监听，自动捕获各类事件

通过浏览器全局事件监听，**自动采集，不用每个页面手动写代码**：

1. `window.onerror` / `window.unhandledrejection` 捕获 JS 报错、Promise 异常
2. 重写`fetch`/`XMLHttpRequest`，拦截捕获接口请求异常
3. 监听页面`load`、路由变化，统计页面 PV（页面访问量）
4. 监听点击等事件，采集用户点击行为

## 第三层：统一格式化并脱敏数据

拿到原始采集数据之后，统一整理成后端约定好的数据结构；
**脱敏**：手机号、身份证、用户隐私信息做掩码处理，避免上报敏感信息，满足合规要求。

## 第四层：内存队列 + 本地离线缓存，阈值批量上报；优先 sendBeacon 上报

这一层是**上报优化，核心亮点**

1. **内存队列**：采集到事件先放进内存队列，不是每一条数据立刻发请求（避免频繁 HTTP 请求，压垮后端，影响页面性能）
2. **阈值批量上报**：队列攒到设定条数，或者定时时间到了，一次性批量把多条数据合并成一次请求上报
3. **本地离线缓存 (localStorage)**：用户断网的时候，数据不会丢失，存在本地；等网络恢复之后，继续补发埋点数据
4. **优先使用 sendBeacon API**

> sendBeacon 是浏览器专门给埋点设计的 API。**页面关闭、刷新的时候也能保证数据发送成功**，不会因为页面销毁中断请求；而且它是异步的，不会阻塞主线程，不影响页面体验。如果浏览器不支持 sendBeacon，降级用 fetch。

## 第五层：对外提供手动埋点 API，搭配采样、去重、白名单减少无效上报

- **手动埋点 API**：自动采集覆盖不到的业务自定义事件（比如弹窗曝光、表单提交），业务开发可以调用 SDK 暴露的 api 手动上报事件，例如 `track('button_click')`
- **采样策略**：不用上报全部用户数据，比如 10% 采样，随机只上报十分之一用户的数据，大幅减少上报量，节省服务器成本
- **去重**：防止重复上报同一条事件，避免后端收到重复垃圾数据
- **白名单**：配置只采集指定页面、指定域名，过滤测试环境、内部访问这类不需要的上报，减少无效数据
