# 大文件分片上传

1. 文件大，因为网络波动，容易上传失败，后端可能还有请求体大小限制，需要分片上传，并且通过断点续传保证文件完整性
2. 文件切片：前端通过File.slice()方法分片，将文件切分成2~10MB的片段，每个片段带上 整个文件哈希、分片总数、当前分片
3. 文件秒传：通过spark-md5 生成整个文件的文件hash，如果后端发现已有文件直接返回上传成功实现秒传
4. 断点续传：如果文件不不存在但之前已经有部分分片，后端返回分片数组告知前端进度，前端就可以继续上传实现断点续传
5. 请求控制：控制并发多个请求并且失败重传
6. 合并校验：最后，前端调用统一的合并接口向后端请求合并与校验文件完整性

- 背景与痛点：大文件直传易超时、网络波动易失败、后端有请求体大小限制，需分片+断点续传。
- 前置校验：前端计算整文件 MD5，调用后端 check 接口获取秒传或已传分片列表。
- 切片与哈希：File.slice() 切片，进阶优化：为每个分片单独计算 MD5，确保单片传输安全。
- 秒传机制：后端存在相同 MD5 的完整文件，直接返回成功。
- 断点续传：后端返回已传分片数组，前端过滤后只传未传过的分片。
- 请求控制：控制并发数（如 3-6 个），实现失败分片自动重试（可重试 3 次）。
- Web Worker 优化：大文件 MD5 计算放入 Web Worker 异步执行，避免阻塞主线程。
- 合并与终局校验：后端合并分片，重新计算 MD5 与前端指纹比对，一致则入库，否则报错重传。
