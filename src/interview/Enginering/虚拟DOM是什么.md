## 虚拟DOM本质

1. 本质就是JS对象，通过模拟DOM，在内存中进行vnode创建、diff计算 精准更新视图
2. 虽然虚拟DOM必然比命令式的开发方式性能弱，但通过给开发者提供 声明式UI、状态驱动开发模式，提高项目可维护性、开发效率
3. 虚拟DOM，这些框架也有性能兜底，保证开发效率和性能之间的平衡
4. 虚拟DOM只操作JS对象，通过这一机制将 视图渲染逻辑 和 业务数据逻辑 解耦，实现跨平台特性，除了SPA web应用，还可以在移动端App、小程序、SSR服务端渲染等框架使用，这也是Vue&React作为通用开发框架设计的重要考虑
5. 对于无虚拟DOM、蒸汽模式：
   1. 虚拟DOM运行起来，需要有运行时库维护、管理、调度数据更新逻辑
   2. 无虚拟DOM就是通过编译器去去除运行时vnode与diff开销，把负担迁移到编译时，生成原生的代码，实现精准更新绑定的DOM节点
   3. 颗粒度：比如vue，每次状态变更的单位是 一个个组件，也就是编译后的一个个渲染函数，每次派发更新实际就是调用渲染函数再次执行；而无虚拟DOM的框架，是一个个真实绑定的DOM，比虚拟DOM更精准
   4. 算是拿编译时换运行时性能的落地实例吧，像Fastify后端框架也有类似的操作

## 虚拟DOM的意义

虚拟 DOM 是现代主流前端框架的核心技术。

它在**内存中**使用 JavaScript 对象来描述真实 DOM 节点，通过这种中间层，实现 **状态数据和视图的解耦** ；依靠框架内置的 Diff 算法与批量更新策略，结合声明式 UI、状态驱动的开发模式，实现了 **开发效率与运行性能之间的平衡** 。
虚拟 DOM 本身并不强绑定浏览器 DOM，这也为 RN跨端App、小程序、SSR等的实现提供了技术基础

> JS对象、中间层、解耦视图与状态、声明式UI + 状态驱动、平衡、跨端
