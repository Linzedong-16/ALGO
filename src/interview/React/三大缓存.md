# 三大缓存`React.memo`、`useMemo`、`useCallback`

# React三大缓存API

## 1. React.memo（组件级缓存，高阶组件）

✅ 缓存目标：组件渲染结果（JSX 视图）
✅ 使用位置：包裹子组件定义

```JSX
import { memo } from 'react'

// 用memo包裹子组件
const Child = memo((props) => {
  console.log('子渲染')
  return <div>{props.name}</div>
})
```

原理：组件重渲染前，对比新旧 props（浅比较）

- props 没变 → 直接复用上次渲染结果，跳过组件执行、不重新渲染
- props 变了 → 正常重新渲染

⚠️重点：只对比 props，不保护组件内部 state；如果 props 传函数 / 对象，对比的是引用地址！地址一变，memo 失效。
适用场景：子组件很重、渲染开销大，父组件经常渲染，但传给子的 props 很少变化。

## 2. useCallback（缓存【函数】，hooks）

✅ 缓存目标：函数本身，稳定函数的引用地址
✅ 使用位置：组件内部，写在函数前面

```JSX
import { useCallback, useState } from 'react'

function Parent() {
  const [count, setCount] = useState(0)

  // 缓存这个函数：依赖数组不变，永远返回同一个函数引用
  const handleClick = useCallback(() => {
    setCount(prev => prev +1)
  }, []) // 依赖数组，里面放用到的外部变量

  return <Child onClick={handleClick}/>
}
```

原理：依赖数组里面的值不变，每次渲染返回同一个函数内存地址，不会新建函数
作用：专门解决：把函数传给memo子组件时，每次渲染生成新函数导致 memo 失效的问题。

useCallback 的作用是缓存函数引用。React 每次重渲染都会重新创建组件内的函数，即使函数体一样，引用也不同。如果把这个函数传给 React.memo 包裹的子组件，子组件会因为 props 引用变化而重复渲染。useCallback 能在依赖不变时返回同一个函数引用，从而避免子组件无效重渲染。它本质上是 useMemo(() => fn, deps) 的简写，但语义上专门用于缓存函数

⚠️重点：不缓存函数执行结果！只是缓存函数本体。

## 3. useMemo（缓存【计算值】，hooks）

✅ 缓存目标：昂贵计算的返回结果
✅ 使用位置：组件内部，用来包裹一段计算逻辑

```JSX
import { useMemo, useState } from 'react'

function Demo() {
  const [list, setList] = useState([1,2,3])

  // 只有list发生变化，才会重新执行计算，否则直接拿上次结果
  const heavyResult = useMemo(() => {
    console.log('执行昂贵计算')
    // 模拟非常耗性能的计算：大数组遍历、排序、过滤
    return list.filter(item => item > 1)
  }, [list]) // 依赖数组

  return <div>{heavyResult}</div>
}
```

原理：依赖不变，不会重新执行里面的函数，直接复用上次计算返回的值
作用：避免组件每次渲染，都重复跑一遍重量级、耗时的计算。

⚠️重点：只缓存返回值，不缓存函数；不要把普通代码无脑包 useMemo，本身有开销。

## 三者一句话区分（背诵）

- React.memo：缓存整个组件视图，放在组件定义上，对比 props，防止子组件不必要渲染
- useCallback：缓存函数，稳定函数引用，专门配合 memo 向下传回调函数
- useMemo：缓存计算出来的值，避免重复执行昂贵计算逻辑

## 记忆口诀

> memo 包组件，防子渲染
> useCallback 包函数，稳住引用
> useMemo 包计算，缓存结果
