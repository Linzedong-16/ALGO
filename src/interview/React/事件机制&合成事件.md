## 事件机制和合成事件如何工作

> React 通过在 document 对象 或 root对象 绑定监听器统一调度捕获事件，用事件池 统一处理 原生事件，包装成 合成事件，因此 React的事件回调的 event 参数不是原生的，而是合成事件，并且回调中写异步处理逻辑时如果不主动调用框架提供的 persist 方法、写闭包保存、e.nativeEvent原生对象，无法获得 enent对象

1. 性能：采用事件委托，统一容器绑定侦听器采集原生冒泡的事件，避免监听器过多导致性能的问题
2. 兼容性：统一将原生事件包装成合成事件，内部有对原生事件对象的兼容性处理，抹平浏览器差异如（e.preventDefault方法）
3. 事件池：避免高频的交互中 合成事件 频繁销毁创建，引入了事件池优化，避免GC压力，新版本好像删了这个机制
4. 两次冒泡：一次时原生冒泡收集事件，第二次react在Fiber树中模拟冒泡和分发，找到对应的组件的事件回调执行
