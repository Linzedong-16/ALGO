# useState的机制

## 同步还是异步？

1. 同步提交，延迟执行：setState方法本身是同步的，提交给react会先加入到 队列中等待处理，延迟执行
2. 批量合并，提升性能：一个事件回调中多次调用 setState 方法不会分多次渲染组件，而是通过 react调度合并为一次渲染，提升了页面渲染性能
3. 状态一致性：因为有合并渲染机制，不会出现 中间态的渲染效果，UI状态不完整会影响用户体验

## 函数式更新

> 除了一般的传值更新，还有传入回调函数的函数式更新

1. useState有直接传值 和 传入回调函数 两种更新方式
2. 问题：在一次事件循环中，如果多次用 **直接传值** 的方式更新同一个 state，由于函数组件每次渲染拿到的 state 是闭包快照，所以这几次更新都会基于同一个旧值计算。React 又会在同一轮渲染中做批处理，把多次更新合并，最终生效的通常是最后一次传入的值，所以视图可能和预期不符
3. 原理：**函数式更新的回调会接收** **当前最新的 state（`prev`）** 作为参数。每次调用 `setState` 都会将该更新加入内部队列，在批处理合并时，React 会将 **上一次函数式更新的返回值，作为下一次回调的 `prev` 参数传递** **，从而确保每次计算都基于最新的 state，完美避开闭包陷阱**
4. 最佳实践：每次更新依赖旧值的操作使用 函数式更新
