## 进程和线程区别

1. 定义：进程是操作系统进行资源分配的基本单位，线程是CPU调度和执行的基本单位
2. 关系：进程是相互隔离的；线程隶属于某个进程，一个进程中至少有一个主线程运行，进程中的多个线程共享该进程中的资源，堆内存、全局变量等等，同时，每个线程有自己独立的 执行栈、程序计数器、寄存器
3. 创建销毁开销：进程开销大，线程开销小
4. 通信：进程需通过IPC机制，消息队列、共享内存、管道等实现；线程直接读写共享的变量即可
5. 隔离：进程间相互隔离，不会相互影响；某个线程的异常会导致整个进程的异常以至于影响到其他线程
6. 场景：浏览器是多进程架构，如保证了标签页之间稳定；web服务器是多线程架构，需要处理高并发请求、数据共享等问题

首先，定义是：进程是系统进行资源分配的基本单位，而线程是CPU调度和执行的基本单位。

它们最核心的区别有两点：
第一是 隔离性 ，进程之间是完全隔离、互不影响的；但线程是共享同一个进程内的资源，比如堆内存。
第二是 开销 ，因为进程要分配独立资源，所以创建和销毁的开销很大；而线程非常轻量，开销很小。

最后，在Web开发中的应用：
在后端 ，通常采用 多线程架构 。比如 Java 的 Tomcat，它利用多线程来同时处理海量的并发请求。
在前端 ，浏览器采用的是 多进程架构 。比如每个 Chrome 标签页都是一个独立的进程，这样就算一个标签页崩溃了，也不会影响其他标签页，保证了稳定性。”

> 总结：进程是操作系统资源分配的基本单位，线程是CPU调度的基本单位。线程隶属于进程，一个进程至少包含一个主线程。进程之间相互隔离，通信需借助IPC机制；而线程间共享内存，若某个线程崩溃则会导致所在进程挂掉，但进程间互不影响。在后端，通常通过多线程处理高并发场景；在前端，现代浏览器采用多进程架构，为每个标签页分配独立进程和主线程，确保标签页之间相互隔离，一个页面崩溃不会影响其他页面。这与早期IE的单进程架构不同，当时插件或JS报错极易导致整个浏览器崩溃
